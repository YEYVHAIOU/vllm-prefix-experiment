# EnvBench 派生 `min3500` 高并发压力与承载实验

本文档记录 C76 / C96 / C128 三档高压力实验，用于观察长上下文、多轮工具调用场景下的 GPU KV Cache 压力、服务稳定性、Prefix Cache 复用、Dynamic TTL 与 UCM 外部迁移行为。

该实验使用经过压力增强的 EnvBench 派生工作负载，定位是 **压力与并发承载测试**，与正式 Full Runtime-Eligible EnvBench 派生服务系统回放分开。正式主结果见 `docs/BENCHMARK.md`。

## 工作负载

基础文件：

```text
benchmark/workloads/envbench_high_contention_balanced_min3500.csv
```

该工作负载从 EnvBench 派生 trajectory 中构造，并对小于 3500 tokens 的输入进行压力补长：

```text
pressure_input_tokens = max(original_input_tokens, 3500)
```

因此它保留原始 trajectory 与工具调用结构，但服务端看到的输入长度被有意推高，以增加 GPU KV Cache 压力。它不是“原始 prompt 天然均超过 3500 tokens”的数据集。

C76 基础工作负载包含 76 个 trajectories、1225 个工具事件和 1301 个总请求。压力化后的输入 token 中位数为 3500，最大值为 3988；原始输入 token 中位数为 1451。

容量扩展后：

| 档位 | Trajectories | 工具事件 | 总请求 |
|---|---:|---:|---:|
| C76 | 76 | 1225 | 1301 |
| C96 | 96 | 1540 | 1636 |
| C128 | 128 | 2079 | 2207 |

C76、C96 和 C128 的 trajectory 组成并不完全相同。因此跨档位吞吐更适合观察稳定性和压力趋势；同一档位内 V/U/C/F 的横向比较更严格。

## 四种系统配置

| 配置 | 调度器 | Continuum | UCM | 策略 |
|---|---|---:|---:|---|
| V | FCFS | 关闭 | 关闭 | vLLM 基线 |
| U | FCFS | 关闭 | 开启 | eager WHEN + full WHAT + TieredStore |
| C | Continuum | 开启 | 关闭 | Dynamic TTL |
| F | Continuum | 开启 | 开启 | `cost_full` WHEN + Frontier-Tail K=4 + TieredStore |

U 中的 eager 指 UCM 的外迁选择策略；vLLM 本身没有启用 `--enforce-eager`。

## 稳定性结果

12 个正式运行全部完成预期请求：

| 并发档位 | V | U | C | F |
|---|---|---|---|---|
| C76 | 1301/1301 | 1301/1301 | 1301/1301 | 1301/1301 |
| C96 | 1636/1636 | 1636/1636 | 1636/1636 | 1636/1636 |
| C128 | 2207/2207 | 2207/2207 | 2207/2207 | 2207/2207 |

这些运行均未出现请求失败、OOM、EngineCore crash 或服务端致命错误。当前实验覆盖到并发 128；更高并发没有纳入该压力实验，因此结果只描述已测试范围内的稳定性。

C 的请求吞吐约为 V 的 3.56 倍，Prefix Cache 命中率提高约 68.48 个百分点。F 的吞吐约为 V 的 3.22 倍，Prefix Cache 命中率提高约 67.61 个百分点。

U 在 C76 中选择 15,565 个候选 KV blocks，并全部进入 full WHAT。TieredStore 中 73 个 blocks 进入 DRAM，15,492 个进入 SSD；累计 SSD load 达 196,079 blocks。

F 有 18,522 个 WHEN 候选，进入有效成本判断的为 471 个，最终 `selected=0`。因此没有实际 Tier CREATE / DUMP / LOAD，SSD 仅保留元数据量级内容。

### KV Cache 压力

C 的 GPU KV Cache 占用中位数约 96.47%，P95 约 99.00%；F 的中位数约 96.04%，P95 约 98.94%。`true_free_blocks` 中位数分别约 32 和 29.5。

因此 C128 的 C/F 长时间运行在非常高的 GPU KV Cache 占用区间，同时仍完成全部请求。

### UCM 行为

U 选择并保留 26,220 个 KV blocks，其中 26,147 个进入 SSD，累计 SSD load 为 361,797 blocks。分片结束 SSD 占用约 44.69 GiB。

F 有 30,319 个 WHEN 候选，786 个进入有效成本判断，最终仍为 `selected=0`，没有实际 Tier CREATE / DUMP / LOAD。

## 机制分析

### FCFS 基线的压力主要表现为排队

V 在 C96/C128 的平均 GPU KV Cache 占用并不高，但大量请求停留在等待队列。C96 中 running requests 平均约 5.43，而 waiting requests 平均约 76.99；C128 中 running 平均约 5.40，waiting 平均约 104.24。

因此 V 不是“工作负载没有压力”，而是通过限制同时进入 GPU 的请求数，把压力转化为排队和更高的 TTFT / JCT。

### Continuum 提高前缀驻留与复用

C 在 C76、C96、C128 的 Prefix Cache 命中率分别为 90.45%、87.72% 和 87.61%，明显高于 V 的 21.98%、19.57% 和 17.80%。

同时 C96/C128 的 C/F GPU KV Cache 占用中位数已经接近 95%/96%，说明 Continuum 并不是简单降低并发，而是在更积极地使用 GPU KV 空间保存未来可能复用的前缀。

### eager/full UCM 产生大量外部 I/O

U 的 Prefix Cache 命中率与 V 接近，但三个档位分别产生约 26.48、33.49 和 44.69 GiB 的 SSD 外部存储。按 trajectory 数量归一化后，该存储量约为 0.35 GiB/trajectory，随工作负载规模近似线性增长。

SSD load 与 dump 的累计比例也很高：

| 档位 | SSD dump blocks | SSD load blocks | Load / Dump |
|---|---:|---:|---:|
| C76 | 15,492 | 196,079 | 12.66× |
| C96 | 19,595 | 258,983 | 13.22× |
| C128 | 26,147 | 361,797 | 13.84× |

这表明全量积极外迁带来了大量重复数据搬运，而没有形成足够的 Prefix Cache 收益。

### 成本感知 UCM 避免收益不足的迁移

F 在 C76、C96 和 C128 都得到 `selected=0`。即使 C96/C128 的 GPU KV Cache 已接近满载，成本模型仍判断当前候选的外部迁移收益不足以覆盖 dump/load 代价。

因此 F 没有实际 DRAM/SSD 数据传输，性能主要继承 Continuum 的前缀驻留收益，并增加少量 UCM 决策和 KVConnector 路径开销。

F 相对 C 的请求吞吐差分别约为 9.50%、2.30% 和 7.18%。这些单次压力实验并未用于统计显著性分析，因此更适合作为集成开销的观察结果，而不是严格的概率性结论。

## Dynamic TTL

C/F 在压力工作负载中的工具事件匹配率达到完整覆盖，TTL 命中率在三个档位均接近 98%。

| 档位 | C TTL 命中率 | F TTL 命中率 |
|---|---:|---:|
| C76 | 97.71% | 98.37% |
| C96 | 98.44% | 98.31% |
| C128 | 98.80% | 98.56% |

绝大多数后期事件已经使用 per-tool history，而不是 cold start。这里的工具等待时间使用 `duration_scale=0.01` 和最多 2 秒的回放上限，因此这些数值描述的是当前压力回放条件下的 TTL 行为。

## 与正式 Full EnvBench 派生实验的关系

`min3500` 实验主要回答“在有意放大的长上下文、高 KV 压力下系统如何运行”。正式 Full Runtime-Eligible EnvBench 派生实验则保留更接近原始可运行轨迹的输入长度分布，不进行 `min3500` 补长，并覆盖 1274 个 trajectories、13419 个工具事件和每组 14693 个请求。

两类实验共同表明：

- Continuum 是当前系统性能收益的主要来源；
- eager/full 外迁可能产生显著外部 KV I/O 代价；
- 成本感知 UCM 能够过滤当前工作负载中收益不足的外迁候选；
- Frontier-Tail 与 TieredStore 已完成集成，但正式实验没有触发可单独证明其正向外部 I/O 收益的迁移路径。

完整正式结果见 `docs/BENCHMARK.md`。
